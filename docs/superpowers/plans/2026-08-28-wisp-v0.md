# Wisp v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** In six weeks, deliver a locally persistent Web prototype in which a
new user opens one styled Studio, completes one real poster Brief through a
visible Wisp team, edits and exports the Poster, and displays it in the Studio
within ten minutes.

**Architecture:** Build one TypeScript modular monolith: a React/Vite browser
application, a minimal Fastify generation boundary, and a shared Zod protocol
package. Keep Babylon.js concrete inside `StudioRuntime`, Konva concrete inside
the Poster Workbench, Dexie concrete inside `WorkspaceStorage`, and place one
adapter seam only around paid remote generation. Persist product documents and
stable asset IDs; treat rendering objects as disposable projections.

**Tech Stack:** Node.js 24.20.0 LTS; pnpm 11.24.0; TypeScript 7.0.2; React
19.2.8; Vite 8.2.2; Babylon.js 9.23.0; Konva 10.3.2; Dexie 4.4.5; Zod 4.4.3;
Zustand 5.0.15; Fastify 5.12.1; OpenAI SDK 7.8.0; Vitest 4.1.11; Playwright
1.62.1.

**Spec:**
[`docs/superpowers/specs/2026-08-28-wisp-v0-design.md`](../specs/2026-08-28-wisp-v0-design.md)

## Global constraints

- Read `AGENTS.md`, `CONTEXT.md`, both ADRs, and the relevant protocol before
  each task that changes their boundary.
- Run `.agents/skills/occam/SKILL.md` before adding a dependency, abstraction,
  adapter, registry, protocol field, or extension point.
- Work test-first: add one failing behavior test, observe the intended failure,
  implement the minimum, observe the pass, then refactor while green.
- Keep exactly one local User and one Studio. Do not introduce accounts,
  visits, community publishing, commissions, multiplayer, a general workflow
  graph, or executable plugins.
- Default to deterministic demo generation. No test or ordinary development
  command may require an OpenAI key or spend provider credit.
- Never persist vendor URLs, Babylon/Konva objects, model SDK objects, object
  URLs, API keys, or hidden model reasoning.
- Reject World Kits before rendering unless every path, schema, hash, asset,
  budget, and executable-content rule passes.
- Pin exact dependency versions and commit `pnpm-lock.yaml`.
- Use Conventional Commit subjects shown at the end of each task. Do not mix
  unrelated cleanup into a task commit.
- Before every commit run the task's focused tests plus `pnpm check`. Before
  handoff run the complete verification in Task 13.

## Target repository shape

```text
apps/
├── server/                  # Fastify API and generation adapters
└── web/                     # React UI, workspace, world, workbench, storage
packages/
└── protocol/                # strict persisted/API/World Kit contracts
scripts/                     # deterministic first-party asset generation
fixtures/                    # valid and malicious World Kit fixtures
docs/validation/             # moderated-test guide and evidence template
```

No shared `core`, `utils`, `platform`, renderer registry, provider registry, or
plugin package is created in v0.

### Steps

- [ ] Write failing tests for: one valid document per schema; unknown-field
  rejection; malformed stable IDs; non-finite transforms; a second Studio;
  vendor URLs in stored assets; invalid run transitions; oversized creative
  strings; and response payloads above the configured image limit.

- [ ] Define branded string schemas for `StudioId`, `ProjectId`, `RunId`,
  `AssetId`, and `WispId`. Branding is compile-time only; persisted values stay
  plain strings.

- [ ] Define `WorkspaceDocumentV1` with exactly one `studio`, a project map,
  artifact map, run map, asset metadata map, Resonance ledger, schema version,
  and timestamps. Store Spark availability in run/provider metadata only while
  demo mode costs zero.

- [ ] Define `BriefV1`, `CreativeSpecV1`, `PosterDocumentV1`, and the explicit
  Creative Session state union. Poster layers are a discriminated union of
  `text` and `image`; all assets use stable `AssetId` references.

- [ ] Encode the exact World Kit manifest, scene, style, transform, budget, and
  closed-vocabulary fields from the protocol with `.strict()` objects.

- [ ] Define the API contracts:

  ```text
  POST /api/v1/creative-specs -> CreativeSpecResponseV1
  POST /api/v1/images         -> GeneratedImageResponseV1
  GET  /healthz               -> HealthResponseV1
  ```

  The image response is bounded JSON containing request ID, model snapshot,
  MIME type, base64 data, dimensions, and normalized usage. Decoded image data
  is capped at 8 MiB for v0.

- [ ] Export only public schemas and types from `index.ts`. Do not create a
  generic schema registry or protocol-version negotiation layer.

- [ ] Run:

  ```bash

  corepack pnpm typecheck
  ```

  Expected: every valid fixture parses; every malicious/unknown shape fails
  with an inspectable Zod issue path.
