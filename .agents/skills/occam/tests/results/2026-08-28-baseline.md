# Baseline: 2026-08-28

Three isolated agents evaluated the cases without an Occam skill. Combined
pressures included a six-week deadline, sunk design work, senior authority,
security review, and promises of future extensibility.

## Observed behavior

All three agents made the intended architecture choices:

- Babylon.js remained concrete inside a focused world module.
- World Kit received a strict versioned schema because persistence and trust
  are present requirements.
- Security policy stayed explicit while policy-free mechanics could be shared.
- The external generation vendor received one narrow seam with production and
  test adapters.

The baseline therefore showed no general inability to apply Occam's Razor.
The reusable gap was consistency: future changes need the same evidence,
deferred-scope, reconsideration-trigger, and verification record without
relying on a carefully constructed prompt.

## Authoring consequence

The repository skill must remain a short decision contract. It should not add
line-count scorecards, mandatory Rule-of-Three folklore, a fixed architecture,
or a generic prohibition on interfaces. Its value is keeping Wisp's
reversibility and trust-boundary tests stable across implementation turns.
